# K8s Local Parity (k3d) — Plan 5 of 5

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `just up-k8s` flow that spins up a local k3d cluster running todo-app via the same Kustomize manifests as production, but without the bits that don't make sense locally (1Password, Cloudflare DNS, Let's Encrypt, Hetzner CSI, ArgoCD). Compose stays the daily inner loop; `just up-k8s` is the "let me verify this manifest change works on real k8s" escape hatch.

**Architecture:** A throwaway k3d cluster on localhost. CNPG operator runs in-cluster (it's the heaviest local install but unavoidable — the app expects CNPG-managed Postgres credentials). The `local/` Kustomize overlay replaces the ExternalSecret with a plain Secret carrying a junk session key. Access is via `kubectl port-forward` to the app Service — no ingress, no TLS locally.

**Tech Stack:**
- k3d (k3s in Docker)
- Same Kustomize manifests as prod; new `overlays/local/` overlay
- CNPG operator (Helm direct install — no ArgoCD locally)

**Spec:** `docs/superpowers/specs/2026-05-18-k8s-deploy-design.md`

**Plan position:** Final of 5. Predecessors: Plans 1–4.

- [ ] **Step 4: kustomization.yaml**

Create `deploy/argocd/manifests/todo-app/overlays/local/kustomization.yaml`:

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

namespace: todo-app-local

resources:
  - ../../base
  - session-key-secret.yaml

patches:
  - path: patches.yaml
  - path: cnpg-cluster-patch.yaml

# Disable the ExternalSecret entirely — local uses a plain Secret instead.
patchesJson6902: []

# We need to NOT include the ExternalSecret in the local overlay. Because
# the base kustomization lists it, we can't `exclude` it — but we can replace
# its content with a no-op patch that retags it as a no-op Kind, OR remove it
# from base via a `delete` directive.
# Cleanest: kustomize's `patches:` with `target: kind: ExternalSecret` and
# `$patch: delete` content. The patches.yaml above doesn't do this because
# the test resource is `kind: ExternalSecret` — let's add it via a separate
# patch.

# Replace todo-app-secrets ExternalSecret with the plain Secret above.
patchesStrategicMerge: []

# Use a JSON6902 delete to remove the ExternalSecret resource:
# (Kustomize requires a non-null patch body; we use $patch: delete in a YAML
# document inside patches.yaml — see the bottom of patches.yaml below.)

images:
  - name: todo-app
    newName: ghcr.io/nickhstr/todo-app
    newTag: bootstrap                     # bump to local image if you build one
```

- [ ] **Step 1: Script**

Create `deploy/local/up-k8s.sh`:

```bash
#!/usr/bin/env bash
# Bring up todo-app on a local k3d cluster, using the same Kustomize
# manifests as production. Idempotent: re-run safely.

set -euo pipefail

CLUSTER="${CLUSTER:-todo}"
NAMESPACE="todo-app-local"
CNPG_CHART_VERSION="${CNPG_CHART_VERSION:-0.22.0}"

# 1. Cluster
if ! k3d cluster list | grep -q "^${CLUSTER} "; then
  echo "[1/5] Creating k3d cluster '${CLUSTER}'..."
  k3d cluster create "$CLUSTER" \
    --servers 1 --agents 0 \
    --port "30000:30000@loadbalancer" \
    --wait
else
  echo "[1/5] Cluster '${CLUSTER}' already exists."
fi

export KUBECONFIG=$(k3d kubeconfig write "$CLUSTER")
echo "  KUBECONFIG=${KUBECONFIG}"

# 2. CNPG operator
echo "[2/5] Installing CloudNativePG operator..."
helm repo add cnpg https://cloudnative-pg.github.io/charts >/dev/null 2>&1 || true
helm repo update >/dev/null
helm upgrade --install cloudnative-pg cnpg/cloudnative-pg \
  --namespace cnpg-system \
  --create-namespace \
  --version "$CNPG_CHART_VERSION" \
  --wait --timeout 5m

# 3. Wait for CRDs
echo "[3/5] Waiting for CNPG CRDs..."
kubectl wait --for=condition=Established crd/clusters.postgresql.cnpg.io --timeout=60s

# 4. Apply local overlay
echo "[4/5] Applying todo-app local overlay..."
kubectl apply -k deploy/argocd/manifests/todo-app/overlays/local

# 5. Wait for app readiness
echo "[5/5] Waiting for app pod readiness..."
kubectl -n "$NAMESPACE" wait --for=condition=Available deployment/todo-app --timeout=5m || true

cat <<MSG

✓ todo-app is up on local k3d.

  Port-forward to reach it:
    kubectl --kubeconfig "$KUBECONFIG" -n $NAMESPACE port-forward svc/todo-app 8080:80

  Then open http://localhost:8080

  Tear down:
    k3d cluster delete $CLUSTER
MSG
```

Create `deploy/local/README.md`:

```markdown
# Local k3d parity

The compose stack (`just up`) is the daily inner loop. This directory adds
a `just up-k8s` recipe that spins up the production Kustomize manifests on
a local k3d cluster — useful for validating a manifest change before
pushing it to a real cluster.

## Differences from prod

| Prod | Local |
|---|---|
| ArgoCD reconciles | Direct `kubectl apply -k` |
| 1Password → ESO → Secret | Plain Secret with a throwaway session key |
| Hetzner CSI volumes | k3s local-path provisioner |
| ingress-nginx + cert-manager + LB | `kubectl port-forward` to the Service |
| 2 app replicas | 1 |
| CNPG 2-instance + WAL archive | CNPG 1-instance, no backup |

## Usage

```bash
just up-k8s            # bring up cluster + app
just down-k8s          # tear down everything

# After 'up':
kubectl --kubeconfig "$(k3d kubeconfig write todo)" \
  -n todo-app-local port-forward svc/todo-app 8080:80
# Open http://localhost:8080
```

## When to use this vs compose

- **compose** (`just up`): daily dev. Hot reload, fast inner loop.
- **k3d** (`just up-k8s`): validating manifests, debugging CRD interactions,
  practicing k8s troubleshooting commands. Slower but real Kubernetes.
- **PR preview** (label PR `preview`): validating against the real cluster.
  Slowest, most realistic.
```
